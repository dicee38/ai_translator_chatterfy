# Chatterfy AI Translator — расширение для Chrome (Manifest V3)

Отдельное, самостоятельное расширение — **не часть** `Chat Summarizer`
(другой проект, другая зона ответственности и чувствительность
данных: там статистика по лидам, здесь — личная переписка с живыми
людьми).

Помогает оператору вести переписку на диалекте собеседника: перевод
по выделению текста и расшифровка+перевод голосовых.

**Полное ТЗ: `docs/TZ.md` — читай его перед началом любой задачи.**
Там термины, архитектура целиком, схема API `messages/v1/search`
(данные берутся из него, не из DOM — см. п.0.1), спецификация
бэкенда-прокси, обе фичи с UI-состояниями и формат манифеста.

## Это копия "на продажу" (создана 2026-10-02)

Эта папка — отдельная от рабочей копия специально для продажи:
**Feature 3 (умный ответ / подсказка ответа) удалена полностью**, без
следа — ни в расширении (`extension/smart-reply.js`,
`extension/smart-reply.css`, попап), ни в бэкенде (`/suggest-reply` в
обеих версиях прокси, включая промпты и оценку стоимости в
`pricing.js`/`openai.js`). Это не ограничение, а сознательное решение
по просьбе оператора — не часть продаваемого продукта.
Рабочая копия с Feature 3 (личный инструмент владельца) — отдельная
папка `translate` рядом с этой, её не трогать.

## Товарная упаковка (решение от 2026-10-02)

Расширение готовится к продаже как решение другим операторам.
**Feature 1 (перевод) и Feature 2 (голосовые) — всегда включены**,
без переключателей в попапе. Это и есть весь продаваемый продукт —
Feature 3 в этой копии не существует (см. раздел выше).

- Адрес прокси/токен и расход бюджета теперь видны прямо в обычном
  попапе (не спрятаны) — по модели продажи каждая компания вводит
  туда СВОИ значения (свой прокси, свой токен), это не внутренняя
  настройка владельца, а обязательный шаг покупателя.
- **Критично перед реальной продажей:** `extension/shared-defaults.js`
  всё ещё указывает на `localhost:8787` — для любого покупателя,
  который не зайдёт в скрытые настройки сам, расширение просто не
  заработает. Нужно либо поменять дефолты на реальный прод-адрес (но
  тогда токен в них — секрет в git, чувствительно), либо продумать
  процесс выдачи адреса/токена каждому покупателю при установке.
- **Модель продажи уточнена (2026-10-02): не общий сервис, а
  инсталляция на компанию.** Каждая компания-клиент разворачивает
  **свой** прокси и подключает **свой** `OPENAI_API_KEY` — чужого
  бюджета в этой схеме не существует, риск "покупатель вскрыл
  расширение и дёргает наш общий прокси" снят архитектурно, отдельный
  токен-на-покупателя поверх этого не нужен. Осталась другая, уже
  внутрикомпанийная задача — см. Этап 7.

## Архитектура (не менять без явной просьбы)

```
content script (v2.chatterfy.ai) → свой бэкенд-прокси → OpenAI (транскрипция, перевод)
```

- **Данные — из API, не из DOM.** `POST /api/messages/v1/search`
  (`{chat_id, limit}`) отдаёт всю историю чата: `content` (текст),
  `sender_type: "incoming"/"outcoming"` (собеседник/оператор),
  `files[]` с `type: "voice"`, прямым `url` на `.ogg` и
  `meta.duration` — этого достаточно и для контекста диалекта, и для
  списка голосовых. DOM парсится **только** для позиционирования
  кнопок/плашек рядом с нужным сообщением, не для самих данных.
- **Ключ API никогда не в расширении.** Content script стучится в
  свой бэкенд-прокси (Cloudflare Workers или VPS — см. `docs/TZ.md`
  п.3.5), прокси держит ключ OpenAI и вызывает его сам. Один вендор на
  всё (транскрипция, перевод) — один ключ, не два.
- **Прокси обязателен: авторизация + бюджетный лимит.** Без токена на
  запросах к прокси и без дневного/месячного лимита по стоимости —
  прямой риск слить весь баланс API. Оба пункта — не опция, часть
  MVP с первого этапа (см. `docs/TZ.md` п.3.2–3.3).
- **Прокси не хранит контент дольше самого запроса.** Это переписка
  с реальными людьми — логировать текст/расшифровки на бэкенде
  дольше, чем нужно для ответа, не надо (см. `docs/TZ.md` п.3.4, 8).
- Обе фичи — **read-only помощь**, ничего не отправляется и не
  меняется в Chatterfy автоматически.
- **Поле ввода сообщения — Quill (`contenteditable`), не
  `<input>`/`<textarea>`.** Вставка текста (кнопка перевода в поле
  ввода, `compose-translate.js`) — через
  `document.execCommand('insertText', ...)`, не через React-инпут
  трюки.
- `manifest.json` — узкий `host_permissions` (конкретные домены
  Chatterfy + свой прокси), не `<all_urls>` как у Chat Summarizer —
  этому расширению не нужен доступ ко всему интернету.

        сотрудника компании вместо одного общего `EXTENSION_TOKEN`
        (обратная совместимость сохранена: если не задан, старый

        на токен, отдельно от суммы в долларах; ловит зацикливание/баг.
        429 с `error: 'rate_limited'`, расширение (`background.js`)
        различает его от `'budget_exceeded'` по полю `error`, не только
        по статусу.
      - `ALERT_WEBHOOK_URL` (опционален) — разовый POST-вебхук при
        пересечении 80%/100% дневного бюджета компании, без контента
        переписки, только агрегированные суммы.
      - `GET /admin/usage` (свой `ADMIN_TOKEN`, не операторский) —
        расход за сегодня/месяц по компании и по каждому сотруднику
        отдельно.

        месячный расход компании, если проски их возвращает (health

        знать, чей именно суб-лимит показать).

        расходов прямо в дашборде OpenAI (Billing → Limits) — это
        единственная защита, не зависящая от правильности собственного
        счётчика прокси (а он уже один раз ошибался на порядок, см.
        Этап 1 про калибровку цены транскрипции).
      - Покрыто `npm run test:skeleton` в обеих версиях прокси
        (per-employee суб-лимит, rate limit, `/admin/usage`) — логика
        проверена, реальный прод-деплой с этим набором переменных не

## Как работать

Ссылайтесь на конкретный этап в промпте, например:

```
Реализуй этап 2 из docs/TZ.md: скелет бэкенда-прокси с /translate и /transcribe
```

Claude Code сам откроет `docs/TZ.md`, найдёт нужный раздел (архитектуру,
формат эндпоинтов, промпты) и будет держать в контексте правила из
этого файла на протяжении всей сессии.
